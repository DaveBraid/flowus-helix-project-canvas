# 实验记录与验收

沿用目标 Stage 的实际层级。将「实验结果」和「实验结论」放在「行动结果」下，保留人工栏目、批注、引用、原始附件和未涉及的内容。旧 Stage 的栏位有差异时，先定位现有结果区；无法安全定位时，交付草稿并报告所缺的写入位置。

## 排版

- 用**加粗**突出关键结论、主要数值差异或影响判断的条件。优先强调短语，把并列的结果、条件或待验证项组织成列表。
- 用行内代码呈现需精确辨认或复制的命令、路径、文件名、配置键、运行 ID、模型标识和提交哈希。多行命令使用代码块。
- 对话和草稿使用 Markdown。写回 FlowUs 时，在对应的原生富文本上设置 `annotations.bold: true` 或 `annotations.code: true`。段末的 ` ✧` 保持普通文本，符号前保留一个半角空格。

## 实操细节与证据折叠

正文按问题、做法、关键观测和结论推进。保留影响判断的条件、差异和不确定性，确保折叠收起时仍能读懂本阶段的主要结果和结论。

- **行动方案下的固定布局。** 在人工填写的宏观方案之后、下一栏目之前，依次放置同级原生分割线 `divider` 和 `具体行动 ✧` 折叠列表 `toggle`。开工前写入拟执行步骤，执行后补充接手者需要的实际步骤、命令、参数或环境信息。已有对应的分割线和折叠时复用，增量维护子块。
- **按内容决定记录和位置。** Agent 根据本阶段的问题、证据和接手需要，选择值得保留的细节，并在授权范围内决定写入位置。保留复现、核验证据和接手所需的过程、配置及原始材料入口。简短且紧贴叙述的细节可随正文呈现，展开会打断主线的细节可在相关叙述附近折叠。按实际内容决定折叠的分组、标题和位置，使用原生 `toggle` 并按块末规则标记新增标题。需要集中存放版本信息与证据入口时，可用「版本与原始证据」作为标题。

## 证据与表达

- **实验结果写事实。** 写实际执行、关键设置、直接观测与证据位置。分清本轮直接核验、历史记录和用户反馈。计划、预期和原因假设保留其性质。材料冲突时注明来源及条件，证据缺失时交代受影响的判断。
- **让每组实验回答一个明确问题。** 交代它验证什么、比较对象改变了什么、哪些条件可比、指标测量什么及其单位和方向，再写观察支持的判断。消融实验说明移除或替换的内容，以及比较能区分的因素。区分指标定义、坐标系、时间窗口、百分点和相对变化等会影响理解的差异。
- **实验结论回答阶段问题。** 说明与基线或预期的差异、证据支持的判断、成立条件和待验证项。保留失败和异常。因果归因需要能区分因素的对照，按实际证据强度描述结论。
- **保留可追溯的来源。** 使用稳定的来源链接，远程文件写明主机和路径。多轮结果保持各自配置与产物的对应关系。局部更新先读前后文，再使新增内容接上当前问题和已有记录。

## 避免防御性写作

- 直接交代测试范围、统计口径和可比条件。终审时判断删掉一句是否会改变读者对实验或证据的理解。保留影响判断的条件，删去纯自证、无关否定和重复提醒。工具调用和编辑过程留在交付汇报。
- 判读提醒紧跟它对应的数字、表格或观测。先说明数据怎么来的，再交代读者应怎样理解。容易误读时，可用「注意」或「值得注意的是」自然引出提醒，并说清依据，例如窗口共享了哪些数据、标签由哪种筛查方式产生。提醒词按需使用。
- 结论或判断缺少铺垫时，在句前或句后用一两句话交代指代、定义、原因或成立条件。例如说提前终止的分支仍可贡献候选窗口时，就地说明终止前须已采集齐该窗口所需的历史和未来数据。解释以已核实的方法和证据为准，依据不足时将表述收束到已观察到的事实。

## 图表与数字

- 连续变量、训练过程、时间序列和多组趋势优先用曲线。同一批数据已有清楚的曲线表达时，避免重复列成表。需要查阅离散配置、分组或少量关键值时，用 FlowUs 原生表格，只保留必要列。新建简单表格默认显式设 `table.width_mode: "adaptive"`，用户指定样式时从其要求。
- 保留原图、原始附件和原始数据入口。仅使用实际数据生成结果图表，注明来源、指标、单位、对照与必要的采样或处理方式。图表放在相关叙述附近。图注说明图中对象与条件，正文帮助读者找到比较对象、理解观察和它支持的判断。
- 正文先说差异的方向和幅度，引用影响判断的关键数值。完整精度留在图、表或原始材料。差异小就按实际写，保留会改变判断的异常与不确定性。
- 使用公式时，独立公式用原生公式块，行内公式用原生数学富文本。说明理解所需的关键符号和单位。工具无法可靠落页时，提供可用草稿并指出具体缺项。

## 实验附件

- 将能帮助读者理解或核验结果的曲线图、截图、演示视频等随报告写回。核对附件对应的运行、版本和场景，放在相关叙述附近。简短说明读者应关注的条件或现象，图注和视频说明按 Agent 标记规则处理。
- 复用可用的 FlowUs 内部文件，或把本地实验附件上传到目标 Stage。按当前接口插入可预览或播放的原生媒体块，其他材料用附件块。可追溯的原始证据入口可以保留稳定链接。
- 回读媒体块和文件引用，能预览、播放或下载时核验实际内容。个别附件遇到权限或工具限制时，完成其余写回并报告具体缺项。

## Agent 标记

- 本次新增或实质改写的可见文字在**块末**标一次 ` ✧`，符号前恰好一个半角空格（U+0020）。同一段有多句时只标段末。列表项、图注、表注和新生成的标题各在自身末尾标一次。经授权实质改写的混合段落也按整段标记。
- 原样引用、未改写的人工内容和来源元数据保留原样。Agent 整理的简单表格用表注或相邻说明标记，保留单元格数据。代码、纯公式、URL、标识、原始数字及图片本体保持原样，Agent 生成的说明照常标记。仅处理本轮生成或实质改写的内容。

## 写回与收尾

1. **先做内容终审。** 从接手者的角度通读，确认能看懂这轮为何开展、怎样比较、哪些结论有证据、还有什么待验证。回查结论与图表、配置和来源能否对上，修补必要衔接。
2. **写前记下原结构。** 对获授权的目标确认 Project、Stage ID、实际字段和写入位置，记下目标块、相邻人工内容、顺序、附件及有关属性。按当前接口做必要的原生块增量更新。遇到并行修改先重读；写入结果不明先回读，避免重复追加。
3. **写后对账。** 回读同一 Stage，核对块的实际位置、正文、图注、表头、行列、数值、公式类型和附件引用。对新增或改动的折叠，核对标题、子块和所在栏目。维护「具体行动」时，核对分割线紧接人工方案且折叠在分割线之后。检查原生富文本中加粗、行内代码与 ` ✧` 的实际范围。同时确认未授权变动的人工栏目、内容、附件和顺序保持原样。根据实际核验区分块元数据、内容可用与界面显示。
4. **分开汇报实验、记录、附件。** 按实测和项目验收口径说明实验进展，返回已写回的页面及尚缺材料。用户要求维护完成状态时，先核对必需证据与内容，再用现有原生字段记录实际完成时间，保留已有开始时间。人工尚未填写下一阶段问题时，已完成的结果照常交付。
5. 清理本轮临时文件、进程和临时标签页，保留正式证据与运行产物。

规则参考 [FlowUs Recording Rules](https://github.com/NanHaibei/flowus-recording-rules/tree/5aa6a8dd55b78e4074b5edda5bd0dcb611632f64) 的实验报告、内容组织和写回检查，以及 Loom 的反防御性写作规则。
