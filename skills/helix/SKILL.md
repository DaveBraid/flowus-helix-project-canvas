# Helix

FlowUs 是唯一业务数据源。通过 Helix 专用 MCP 复用服务的归属校验、模板复制、连续编号和冲突保护；不要用通用 FlowUs 工具绕过这些逻辑。

## 操作约定

- 先调用 `helix_help` 并读取当前工具契约。项目与图使用 `helix_project*`、`helix_experiment*` 和画布工具，正文与附件使用 `helix_content_*`、`helix_file_*`；完整路由见 [MCP 使用说明](references/mcp-usage.md)。工具未提供的能力应明确报告，不能猜测接口或自行降级绕过服务。
- 先定位项目，再定位实验。以稳定页面 ID 提交操作；标题、项目 URL 名和阶段编号只用于检索或展示。编号会随关系和删除变化，不能当作 ID。
- 写入前读取当前目标、可选状态及相关来源。只修改用户要求的属性、正文块、附件或画布字段，保留其余内容。区分正文追加、局部更新和整体替换。
- 现有授权覆盖的操作直接执行，无需逐次确认。目标不明确或操作超出授权时，先处理确定部分，再询问缺失信息。
- 删除前调用 `helix_delete_preview` 核对目标及下游引用影响；将返回的 `confirmTargetId` 和 `revision` 交给 `helix_delete`，按已授权范围执行软删除。服务以同一对象的官方删除回执确认成功，不依赖删除后 GET。实验删除会清理后续实验指向它的来源并重编，不自动跨接；恢复不重建已移除关系。当前页面级授权下恢复仍为 403、可用性待验证；不得自行扩大底层授权。

## 业务规则

- 新实验必须走服务模板流程；来源必须属于同一项目的实验表。多个来源分别提供问题输入，不能自行合并成一段。
- 模板生成的正文是创建时快照。之后改来源关系不代表重写已有正文；需要更新正文时另按用户要求操作。
- 编号由服务根据来源 DAG 连续生成，删除后重编；不要手工承诺固定编号或保留空号。循环、归属不明、关系不完整或冲突应停止相关写入，读取最新结果后再处理。
- 状态值从当前实验表结构取得。颜色和布局保存在项目 `Canvas 状态`；使用服务支持的操作，不手写覆盖整个 JSON。
- 正文分页用 `helix_content_read`；追加与块修改分别用 `helix_content_append`、`helix_content_update`。保留已有块类型，不注入对象父级、子页、引用或媒体块。
- 附件用 `helix_file_prepare` 申请上传，按返回的 method/headers 上传原始字节，取得实际 PUT 的 200/201/204 响应后，将该值作为必填 `uploadStatus` 交给 `helix_file_attach`。单文件不超过 100 MiB；服务只核对本次交易及挂载后块元数据，不独立核实存储字节。
- 创建和追加保留原 `requestId`，不因超时更换。正文追加、附件挂载仅在当前进程去重；未知结果先读回，禁止盲目重放。

## 交付

写后读取实际结果，核对页面 ID、目标字段、来源及正文范围；涉及创建、来源或删除时同时核对编号结果。冲突或部分成功先检查现状，避免盲目重复创建或追加。

精简报告完成项、结果页面和未验证项。不能把工具调用成功直接称为界面显示已验证。清理本轮临时文件及进程。
