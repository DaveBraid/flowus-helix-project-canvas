# Helix 专用 MCP 使用说明

## 定位与边界

Helix 专用 MCP 是研究流程的操作入口，复用 Helix 服务业务逻辑。FlowUs 保存项目、实验、来源、正文、附件和画布状态；服务缓存可以丢弃，不构成另一份业务数据。

使用前发现当前连接提供的工具，并读取工具描述与参数。以下工具对应本仓库实现，实际可用性以运行中的契约为准。部署入口示例：`https://helix-mcp.example.com/mcp`，替换为自己的 HTTPS 域名；每个部署均需验证公网连接与客户端接入。没有对应工具时，报告缺口，不调用通用 FlowUs 工具绕过编号、模板或归属校验。

## 工具路由

| 任务 | 工具 | 关键参数或结果 |
| --- | --- | --- |
| 工作流与契约 | `helix_help` | 返回当前工具、范围和限制；首次操作先读。 |
| 列出与读取项目 | `helix_projects_list`、`helix_project_get` | 先取稳定 `projectId`；读取图、状态选项及布局。 |
| 创建项目 | `helix_project_create` | `title`、唯一 `slug`、固定 `requestId`；初始化背景区、独立实验表及嵌入。 |
| 修改项目 | `helix_project_update` | `projectId`、`revision`；局部改标题、简写或额外原生属性。 |
| 新建资料页 | `helix_page_create` | `parentId` 为项目内页面，固定 `requestId`；不用于创建实验。 |
| 新建与修改实验 | `helix_experiment_create`、`helix_experiment_update` | 来源用 `sourceIds`；更新用 `experimentId`、`revision`；状态用 `status`。 |
| 连续重编 | `helix_graph_reconcile` | 真实来源关系驱动重编，返回实际更改数和图。 |
| 保存画布 | `helix_layout_save` | `revision`、完整节点 `positions`，可带 `cardColor`；不保存视口。 |
| 核对、删除与恢复 | `helix_delete_preview`、`helix_delete`、`helix_restore` | `projectId`、`targetId`、`kind`；删除额外带预览返回的 `revision`、`confirmTargetId`。 |
| 分页读正文 | `helix_content_read` | `targetId`、`kind`；返回游标后原样续读，每次为一页直属块。 |
| 追加正文 | `helix_content_append` | `targetId`、原生 `children`、固定 `requestId`；单次最多 100 块。 |
| 修改块 | `helix_content_update` | `blockId`、同类型正文 `patch`、`revision`；版本仅作预检。 |
| 申请与挂载附件 | `helix_file_prepare`、`helix_file_attach` | prepare 返回上传信息和 `uploadId`；实际 PUT 成功后，attach 必须带真实 `uploadStatus`（200/201/204），并读回挂载块元数据。 |

额外属性 `properties` 不能覆盖来源、状态、编号或 Canvas 等受保护字段，按工具用途走专用参数。实验额外属性与标题、状态、来源修改分两次调用，每次读取最新版本。关联必须位于当前项目内；字段声明的关联目标表约束仍由 FlowUs 校验。

## 定位对象

1. 读取项目候选，结合用户给出的名称、URL 名或链接定位。
2. 读取该项目的实验，确认标题、来源和状态。
3. 使用返回的项目页面 ID、实验页面 ID、正文块 ID 或附件 ID 进行后续操作。

项目 URL 名可以修改，实验阶段编号会重编。二者不能代替页面 ID。候选不唯一时只询问具体目标，不猜测写入。

## 操作要求

| 范围 | 操作与核验 |
| --- | --- |
| 项目 | 先读取当前属性和直属实验表。创建或修改后核验页面 ID、属性及表归属；不把普通页面误作项目。 |
| 新实验 | 复用服务模板和来源快照逻辑。模板问题输入逐来源保留；创建后读取新页面、来源、状态及连续编号。 |
| 来源关系 | 仅引用同项目实验表内的页面 ID。修改前核对原来源与新来源，修改后读取完整关系和重编结果。 |
| 状态 | 从当前表结构读取可选值，使用实际支持的状态；不自行添加选项。 |
| 正文 | 明确追加、指定块修改或替换范围；保留未授权修改的块、嵌套结构及附件。 |
| 附件 | 使用契约支持的上传与挂载流程，核验内部文件引用及目标正文位置；不以外部图床替代。 |
| 卡片颜色 | 使用服务颜色字段与校验，读回颜色；不覆盖坐标或其他 Canvas 字段。 |
| 布局 | 读取当前图及版本，使用服务支持的布局操作；保留颜色和其他 Canvas 字段。节点不可拖动，缩放和平移不写 FlowUs。 |
| 软删除 | 核对项目、实验页面 ID 及下游引用；服务按同一对象的官方回执确认删除，再移除后续实验指向它的来源并重编，保留其他来源，不自动跨接。核验回执、剩余关系及重编；部分完成按警告处理。 |

用户现有授权涵盖的写操作直接执行。授权未涵盖的删除、正文覆盖或其他目标需询问；不额外要求每次普通写入确认。

## 编号与正文

阶段编号由服务根据当前来源关系连续生成。推进与合并使用大号，分支使用小号；同大号的分支小号全图去重。编号只负责展示和排序，关系始终引用页面 ID。删除实验后，后续实验移除指向被删记录的来源，保留其他来源，不自动连接到被删记录的上游；随后重编，后续显示编号可能改变。恢复记录不会重建已移除的来源关系，需另按用户要求调整。

新实验正文来自配置的普通模板页面。每个来源实验的“下一阶段聚焦问题”分别形成新实验的问题输入。来源关系后续变化、来源正文后续修改，都不会持续同步这份创建快照。需要改正文时，单独限定修改范围。

服务拒绝模板中不支持的块时，应报告具体限制，保留原记录；不要静默跳过块后声称复制完整。

## 正文与附件限制

正文操作支持段落、引述、折叠、标题、列表、待办、代码、公式、分隔线、提示块、表格和分栏的已支持字段。富文本仅接收文字与公式，提示图标仅接收 emoji。通用正文操作不接受子页、子数据库、同步块、页面引用或媒体；新简单表格默认 `width_mode: "adaptive"`。读取返回游标时需继续分页；子块按需要另外读取。

附件先 `prepare`，再按返回的 method/headers 上传原始文件字节。只有取得实际 PUT 成功响应后，才能调用 `attach`，并将响应状态作为必填 `uploadStatus`：仅允许 200、201 或 204，不得推测或伪造。单文件为 1 字节至 100 MiB，MIME 使用工具枚举。

服务只认可本进程 `prepare` 返回、且属于当前项目页面的上传交易。追加内部文件后，服务 `GET` 新块并核对 `oss_name`、`size`、`content_type`，成功返回 `verification: "client-put-receipt-and-flowus-block-readback"`。这验证客户端 PUT 回执与 FlowUs 块元数据，不独立核实存储中的真实字节；不要将其汇报为下载校验或文件哈希验证。实测私有 CDN 的 `file_url` 直接 HEAD/GET 返回 403，服务不直接读取私有 CDN。

已有附件不因上传新文件而删除。追加成功后若块读回失败，应报告附件可能已提交，先核对页面，禁止盲目重放。

## 冲突与部分失败

- 版本冲突：重新读取当前记录或画布，核对用户意图，再按最新契约提交。
- 创建或追加保留原 `requestId`；相同请求不能改内容。结果不明时先读取实际页面或块，避免重复。
- 正文追加和附件挂载仅在当前进程去重，未知追加结果禁止自动重放；服务重启不提供持久去重保证。
- 块更新的 `revision` 仅作预检；软删除也没有官方原子版本锁，不能宣称完全消除读取与写入之间的竞态。
- 编号更新部分成功：报告已完成范围和剩余错误，按服务提示读取最新图；多页更新不具有跨页事务。
- 来源循环、关系不完整或归属异常：停止相关写入，报告具体问题；不手工补号掩盖异常。

## 当前底层授权限制（2026-10-27）

页面级 FlowUs 授权已实测：首次官方 API `DELETE` 成功，删除后的 `GET`、重复 `DELETE`、`PATCH` 恢复均为 403。删除确认逻辑已修复：接受同一对象明确返回 `in_trash: true` 的官方成功回执，随后失效缓存、清理后续来源并重编，不依赖删除后再读目标。回执不完整不能当作成功；`needsReconcile` 或警告表示仍需核对后续处理。

当前授权下恢复仍为 403，恢复可用性待验证。删除成功后不要为取得读回而盲重试删除。重复删除幂等能力依赖底层还能读取回收站对象，当前连接不具备该条件。

CLI 没有可用软删除命令，不代表官方 API 不支持 `DELETE`。服务实现包含删除及恢复路径，但端点存在不等于当前授权具备调用能力。是否扩大服务器底层授权须由用户决定；即使底层授权扩大，AI 工具范围仍限配置的 Helix 项目及其后代。
